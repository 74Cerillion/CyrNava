# ADR-003: Local FastAPI, SQLite and filesystem storage

Status: Accepted implementation, recorded retrospectively during M6.

## Context

The workspace must work offline and keep user data outside source control.

## Decision

Use loopback HTTP, parameterized SQLite transactions and generated local asset paths under an XDG profile. M6 serves the built frontend on the same origin.

## Alternatives considered

Browser-only persistence; remote database/cloud storage; storing binary images inside SQLite. Alternatives listed here are an M6 comparison; no undocumented past deliberation is asserted.

## Rationale and evidence

M1/M2/M4 establish the durable local boundaries; M5 adds coordinated offline backup. SQLite needs no server installation. Evidence: current source, root milestone reports and available Git history through M5 `5fa4dab`.

## Accepted tradeoffs

DB and image files cannot share one atomic transaction; normalization, reconciliation and conservative ownership manage that boundary. Linux advisory locks are cooperative.

## Consequences

No cloud runtime dependency; back up database and assets together. This architecture does not provide authentication or protection against local malware.
