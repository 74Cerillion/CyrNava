# ADR-001: BlockNote through a frontend adapter

Status: Accepted implementation, recorded retrospectively during M6.

## Context

Rich editing requires an editor-specific schema, events and upload hooks.

## Decision

Keep BlockNote imports and schema in KnowledgeEditor.tsx; expose application-owned JSON and flushUploads to PersistentNote.

## Alternatives considered

Direct BlockNote calls throughout App; a custom editor; another editor library. Alternatives listed here are an M6 comparison; no undocumented past deliberation is asserted.

## Rationale and evidence

The adapter already exists in M0–M5 and limits UI coupling without hiding the stored document format. Evidence: current source, root milestone reports and available Git history through M5 `5fa4dab`.

## Accepted tradeoffs

Replacing the editor still requires a document migration and new rich-browser tests.

## Consequences

Keep navigation and HTTP clients independent of editor APIs; test adapter behavior and actual browser editing.
